Module Algostream_data_ingestion.Data_quality

Real-time market-data quality monitors.

Sequence-gap detection is parser-side: it runs BEFORE the bus publish so a backpressure-driven try_publish drop cannot cause a false-positive gap alert downstream. Stale-tick and crossed-book checks are evaluated on the parsed payload and instruct the connector whether to publish, drop, or emit an additional Risk_alert.

What sequence must be

Some n enables gap detection, and commits the caller to a specific guarantee: n is a per-symbol counter that increments by exactly one for each message this connector actually receives. Anything else makes dropped_to_gap meaningless, and it will be meaningless quietly — every message will look like a gap and the counter will read in the millions.

Two feeds already got this wrong. Coinbase's sequence field counts the product's whole full channel while the connector subscribes only to matches, and Binance was passing the trade timestamp in milliseconds, so the reported "dropped" count was the elapsed time between trades. Both now pass the exchange's per-symbol trade id, which is dense over the messages received.

None disables gap detection for that message. Use it when the feed offers no such counter — which is the case for every tick stream here, since neither exchange numbers its quote updates.
